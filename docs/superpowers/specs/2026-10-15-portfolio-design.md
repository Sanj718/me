# Portfolio site — design

## Goal
Replace the old GLSL portfolio (`Sanj718/my-glsl`) with a simple, clean personal site for
Sanjar Sobirjonov (Shopify / JS developer, Ottawa, works at Polaris). Deployed to
`Sanj718/me` via GitHub Pages at `sanjar.dev`.

## Constraints
- Visual language is **Shopify Polaris web components, v2.0 release candidate**
  (`https://cdn.shopify.com/shopifycloud/polaris-2.0-rc.js`). No App Bridge, no API key meta tag
  (verified standalone in a probe).
- Stay within Polaris components and tokens; no decorative custom art, no shader hero.
- Plain static files, no framework, no build step. Must work on GitHub Pages and when opened
  directly from disk (`file://`): classic `<script>` tags only, no ES modules, no fetch of local files.
- Polaris script URL lives in one place so moving to stable `polaris-2.js` is a one-line change.

## Concept: "portfolio as a Polaris app"
One page that behaves like a well-built Polaris admin screen. Personality comes from
composition and interaction, not decoration.

| Section | Components | Behaviour |
|---|---|---|
| Header | `s-heading`, `s-text`, `s-avatar`, `s-badge` | Name, role, location/status badges |
| Status | `s-banner` | One-line "currently working on" notice |
| Projects | `s-grid`, `s-clickable`, `s-chip`, `s-search-field` | Search + tag filter; card opens `s-modal` with details and links |
| Experience | `s-table` | Role, company, years, stack |
| Stack | `s-chip` group | Doubles as the project tag filter |
| Contact | `s-button`, `s-link` | GitHub, LinkedIn, email, X |
| Theme | `s-switch` | Light/dark toggle, defaults to system |

## Files
```
index.html   # markup + Polaris script tag
app.js       # project/experience data arrays at top; filter + modal logic
style.css    # minimal overrides only (page background, column width)
CNAME        # sanjar.dev
.nojekyll
```

## Content
Drafted from GitHub (bio "Shopify / JS", Ottawa; repos incl. Shopify-MinicartJS,
functions-hub, section-conditions, minica, xapps, avex-next). LinkedIn has not been provided,
so the experience table is drafted from public GitHub data and **must be reviewed by the owner**
before deploy. All content lives in the data arrays in `app.js` so edits are trivial.

## Error handling / degraded modes
- If the Polaris script fails to load, the page remains readable as plain semantic HTML
  (content is real text inside custom elements, not generated by JS).
- Filter/modal logic degrades gracefully: with JS off, all projects are visible as links.

## Testing
- Manual: open `index.html` directly in the browser (`file://`, no local server), check light/dark, mobile width (~375px), filter, search, modal open/close
  with keyboard, no console errors.
- Verify links and the CNAME file before deploy.

## Deployment (each step needs owner confirmation)
1. Push to `Sanj718/me` (currently empty), enable Pages from `main`.
2. Remove `CNAME` from `Sanj718/my-glsl` (it currently claims `sanjar.dev`).
3. Set custom domain `sanjar.dev` on the new repo; DNS to GitHub Pages IPs/`Sanj718.github.io`.

## Out of scope
Blog, CMS, analytics, contact form backend, shader/GLSL showcase.
